# Fala — מדריך לבעל האפליקציה ולהעברת הפרויקט

המטרה של התיעוד היא שאפשר יהיה לפתוח את הפרויקט עם Claude Code, GitHub Copilot או סוכן אחר ולהמשיך לעבוד בלי לשחזר שיחות קודמות. ההוראות, מבנה המערכת, כללי הפרסום ותיעוד הגרסה נשמרים ב־GitHub יחד עם הקוד.

## איפה מתחילים

- [מפתח לכל התיעוד](README.md).
- [מסמך כניסה למפתח או לסוכן חדש](agent-handoff.md): איפה כל חלק בקוד, איך מריצים בדיקות ומה עדיין לא נבדק.
- [הוראות עבודה עם Claude ו־Copilot](agent-setup.md).
- [נוהל פרסום גרסה](releasing.md): מהכנת הגרסה ועד אימות באתר וב־Google Play.
- [מה השתנה ואיפה פורסמה גרסה 0.14.0](releases/0.14.0.md).

המסמכים הטכניים באנגלית כדי שמפתחים וסוכנים שונים יוכלו להשתמש בהם בקלות. המדריך הזה מסביר את התהליך בעברית.

## מה בנוי כאן

| חלק | תפקיד | מתי צריך לעדכן אותו |
|---|---|---|
| אפליקציית Android | המסכים בטלפון, מיקרופון, השמעה, תזכורות והצעת עדכון | שינוי במסך או בהתנהגות המקומית מחייב גרסת Android חדשה |
| האתר | תרגול בדפדפן, כולל שימוש ב־iPhone ובמחשב | פרסום האתר מעדכן את קובצי האתר |
| השרת | שאלות, בדיקת תשובות, התקדמות, נקודות, הגדרות והודעות | שינויים בצד השרת מגיעים גם ללקוחות קיימים, בלי התקנה מחדש |
| מסד הנתונים | חשבונות, שיחות, התקדמות והעדפות | שינוי במבנה או בברירות המחדל עשוי לדרוש עדכון נתונים נפרד |
| Google Play | הפצת האפליקציה החתומה לבודקים | צריך להעלות חבילה חדשה או לקדם חבילה שכבר הועלתה |

אלה חלקים נפרדים: העלאה לאתר לבדה לא מעדכנת את האפליקציה שכבר מותקנת בטלפון.

## מה נעשה ב־0.14.0

- נוספה בחירת עברית או אנגלית לממשק כולו: תפריטים, מסכים, הגדרות, עזרה ופרסים. הבחירה נשמרת בחשבון. בעברית הממשק מוצג מימין לשמאל, והפורטוגזית ממשיכה משמאל לימין.
- התזכורת היומית מופעלת כברירת מחדל ב־17:00 לפי אזור הזמן של המשתמש. העדכון הופעל גם על החשבונות הקיימים; שעות מותאמות שכבר היו פעילות נשמרו. אפשר לכבות, וכיבוי מאוחר יותר נשמר.
- האפליקציה מבקשת אישור התראות ממערכת ההפעלה במקום להסתמך רק על כך שהמשתמש ימצא את ההגדרה בעצמו. אי אפשר להעניק את אישור מערכת ההפעלה בשם המשתמש.
- תוקנו דוגמאות התשובה שחזרו בלי להתאים לשאלה, ונוספה בדיקה שמונעת חזרה לא מוצדקת על אותו זוג תשובות כששאלה משתנה.
- ההשמעה הרגילה ב־Android כבר לא מואטת אוטומטית לפי שדה שהגיע מהמודל. אפשר עדיין לבחור השמעה איטית במפורש.
- נשמר מספר גרסה גלוי והתווספו הערות גרסה ובדיקות.

הדיווח על המתנה של כחמש שניות אחרי שליחה נשאר נושא נפרד למדידה. לא נטען שהפרסום הזה פתר או מדד את הגורם לעיכוב.

## איך מבקשים שינוי נוסף

אפשר לתת לסוכן בקשה כמו:

> קרא את AGENTS.md ואת docs/agent-handoff.md. הוסף את השינוי הבא, בדוק אותו ועדכן את התיעוד. הכֵן גרסה שאפשר לבדוק, אבל אל תפרסם עדיין.

כשמוכנים לפרסם:

> השתמש ב־fala-release וב־docs/releasing.md. פרסם את הגרסה לאתר, ל־Internal Testing ולמסלול הסגור הקיים. אמת את התוצאות ושמור תיעוד של מספר הגרסה, מספר הבנייה ומצב בדיקת Google. אל תפרסם ל־Production.

אם כבר ביקשת לפרסם לאותם יעדים, אין צורך לתת שוב את אותה הרשאה בכל שלב. אם חסרה התחברות לחשבון או שצריך לבטל בדיקה אחרת שממתינה אצל Google, הסוכן צריך להסביר מה בדיוק חסר או מה יוחלף.

## מה קורה בזמן העלאה

1. מעדכנים את מספר הגרסה בכל המקומות ומוסיפים הערות גרסה באנגלית.
2. מריצים בדיקות ובונים את האפליקציה. אם נדרש שינוי במסד הנתונים, מבצעים ומאמתים אותו לפני השרת שתלוי בו.
3. דוחפים את הקוד המוכן ל־GitHub. שינוי בענף הראשי מפעיל את פרסום האתר ואת הבדיקות בענן.
4. אחרי שהבדיקות מצליחות, התהליך בונה חבילת Android עם מפתח החתימה הקיים ומעלה אותה ל־Internal Testing.
5. מקדמים את אותה חבילה, עם אותו מספר בנייה, למסלול הסגור Alpha. אין צורך לבנות מחדש בשביל זה.
6. מאמתים באתר וב־Google Play שהגרסה הנכונה נקלטה, ומתעדים בנפרד אם Google עדיין בודקת אותה.

מספר הגרסה, לדוגמה **0.14.0**, הוא המספר שרואים באפליקציה. מספר הבנייה, לדוגמה **104001**, מוקצה אוטומטית לכל העלאת Android וצריך לעלות בכל פעם. אין להשתמש שוב באותו מספר בנייה.

## איך יודעים שהעדכון באמת זמין

- **אתר:** פותחים את [Fala](https://falachatapp.netlify.app/app/), בודקים את המספר ומנסים את השינוי.
- **Internal Testing:** בודקים אישור העלאה מוצלח לגרסה ולמספר הבנייה הנכונים.
- **Closed Testing:** בודקים גם את מצב הבדיקה אצל Google. אישור שהגרסה נקלטה במסלול אינו בהכרח אישור שהיא כבר הופצה לבודקים.
- **בטלפון:** נדרשים חשבון Google שמורשה למסלול ועדכון של האפליקציה המותקנת. דפדפן מעודכן אינו הוכחה שהטלפון קיבל גרסת Android חדשה.

ברישום הפרסום של 0.14.0 האתר היה פעיל, שני המסלולים הצביעו על בנייה 104001, והמסלול הסגור היה `IN_REVIEW`. זה מצב שנבדק בתאריך הרשום, ולא הבטחה לגבי המצב כעת.

## מעבר למחשב או לסוכן אחר

משכפלים את מאגר GitHub ופותחים אותו בכלי החדש. Claude מקבל `CLAUDE.md`; Copilot מקבל `.github/copilot-instructions.md`; שניהם מופנים ל־`AGENTS.md` ולתיעוד המשותף. ה־skills נמצאים בתוך המאגר ב־`.claude/skills/`.

התחברויות וסיסמאות אינן עוברות דרך GitHub. במחשב חדש צריך להתחבר בדרך הרגילה ל־GitHub ולשירותים הדרושים. מפתחות החתימה והפרסום כבר שמורים בסודות של GitHub Actions, ולכן הסוכן לא צריך להעתיק אותם לשיחה או לקוד.

החלפת כלי הפיתוח אינה מחליפה את ספק הבינה המלאכותית שבתוך Fala. זה שינוי נפרד בהגדרות השרת.

## מה לשמור ומה לא לשמור

שומרים ב־GitHub קוד, בדיקות, מסמכי תכנון, הוראות עבודה, קובצי שינוי למסד הנתונים, הערות גרסה ואישורי פרסום מסוכמים ללא מידע רגיש. שומרים מחוץ למאגר סיסמאות, טוקנים, מפתחות חתימה פרטיים, פרטי התחברות למסד הנתונים ונתוני תלמידים.

אחרי כל שינוי משמעותי מעדכנים את המסמך הרלוונטי. אחרי כל פרסום מוסיפים רישום לתיקיית `docs/releases/`. שינוי תיעוד בלבד לא אמור להעלות שוב אפליקציה ל־Google Play; נוהל הפרסום מסביר איך לדחוף אותו בנפרד.
