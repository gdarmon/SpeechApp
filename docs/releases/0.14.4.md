# Fala 0.14.4 — Vercel release, 27 September 2026

The website/API cutover is live on Vercel. Google Play Internal Testing accepted **0.14.4 (104501)**; closed Alpha accepted the same bundle and was **IN_REVIEW** at 11:37 UTC. Main source is `39ea3c31ddb7b8b67821b9aebd71553d082f7c09`. The strict p95 < 3 seconds gate still fails; the owner explicitly approved releasing this improvement with that remaining limitation.

## Changes

- Release SQL connections during AI generation using durable per-account claims, short transactions and stale-result fencing. Preserve account isolation, idempotency and reward ownership.
- Return the saved turn ID in `X-Fala-Turn-Id`; web renders the existing reply immediately instead of reloading the session. Older APIs retain the GET compatibility path.
- Permit spaced question reuse after two intervening exchanges while retaining immediate-loop, translation and answer-match validation. Keep final-turn continuation instructions consistent with closing the lesson.
- Publish the full website/API on `https://fala-api.vercel.app`. Android's approved origin migration preserves encrypted device login and active-session preferences against the unchanged account database.
- A new matching Web Push key pair was generated and installed in Vercel Production because the previous private key was unavailable through the authorized connection. New subscriptions record their public key; the scheduler never sends/claims using another key. Account reminder times and opt-outs remain unchanged. The new browser origin requires notification permission again.
- A dedicated GitHub Actions schedule invokes the protected Vercel reminder endpoint every 15 minutes. Scheduling is best effort. Netlify must remain only as transitional URL compatibility for old clients until retired; do not enable two schedulers.

## Final full-session and audio evidence

The fifth run completed all 50 sessions, 500 answers, 50 summaries, isolation and idempotent-retry checks without failure. Exactly two requests needed another generation (602 provider calls for 600 operations), versus 52 such requests in the first primary/backup run. 544/600 operations finished below three seconds. Answer-only latency (500 sends) was p50 2.487 s, p95 3.056 s, maximum 4.658 s; 469/500 were below three seconds. Including initial openings and summaries, p95 remained 3.316 s, so the harness intentionally exited **2** for the speed gate, despite complete functional success. Do not discard the four earlier runs or relabel this as an unconditional speed pass.

The measured components in the fifth run were AI p50 1.896 s/p95 2.513 s, SQL p50 150.8 ms/p95 297.1 ms, and outside-handler residual p50 327.1 ms/p95 1.227 s. These percentiles are not additive. The residual includes transport/platform work and is not a measured queue duration. Initial openings had p95 3.714 s; later answers retained occasional repairs and network/provider variability. Real learner devices and cellular networks were not load-tested. Groq's observed quota failures remain a limitation on backup capacity even though it did not cause failure in the final run.

A fresh synthetic-audio check on `fala-api.vercel.app` succeeded: start 1.337 s, generation of the recording 1.889 s, transcription 0.923 s, Send-to-reply 1.978 s. This single clean recording does not establish phone microphone or 50 simultaneous voice-stream capacity.
